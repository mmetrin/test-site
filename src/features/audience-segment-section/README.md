# Блок «Анализируем больше данных»

Публичный компонент — `AudienceSegmentSection`, импорт через `index.js`.
Блок использует React и CSS, без GSAP, canvas и отдельного анимационного движка.

## Структура

| Файл | Ответственность |
| --- | --- |
| `AudienceSegmentSection.jsx` / `.css` | Заголовок, подписи, переключатель аудитории, сетка и отслеживание появления блока |
| `AudienceDataScene.jsx` / `.css` | Композиция слоёв, орбита, вступительные декорации, общие тайминги и масштабирование |
| `AudienceDataChannels.jsx` / `.css` | Горизонтальные линии, бегущий градиентный блик и символы |
| `audienceDataThreads.js` | Детерминированные координаты, длины, яркость и задержки потоков |
| `AudiencePartnerLogos.jsx` / `.css` | Шесть логотипов: появление, рост и лёгкое покачивание |
| `AudienceTransferImpulses.jsx` / `.css` | 24 коротких горизонтальных импульса у логотипов |
| `AudienceCursorTrail.jsx` / `.css` | Зона указателя, синие символы и мягкий локальный blur |

Стили дочерних компонентов импортируются в их JSX. Они используют общие
`--flow-start`, `--growth-duration` и `@keyframes audience-data-appear` из сцены.
Компоненты сцены внутренние: отдельно от неё их импортировать не нужно.

## Запуск и тайминг

`useRevealOnVisible` добавляет `audience-segment-section__content--visible`
при пересечении порога видимости 18%, с нижним отступом области наблюдения 8%.
Срабатывает один раз за монтирование: повторная прокрутка не перезапускает сцену.
Заголовок появляется вместе с контентом блока.

Время ниже отсчитывается от появления класса видимости:

| Время | Действие |
| --- | --- |
| 0–0,8 с | Проявляется надпись Big Data MTS |
| 0–5,2 с | Орбита и логотипы растут от 0,7 до 1; орбита одновременно проявляется |
| С момента появления блока | Потоки и импульсы начинают появляться со своими задержками |

У каждой линии отдельно анимируются появление строки, раскрытие фоновой линии,
движение блика и символов. Блики, символы, импульсы и покачивание логотипов
повторяются; рост и раскрытие фоновых линий выполняются один раз.

## Координаты и настройка

Сцена рассчитана на ширину 1440 px. На экранах 841–1487 px она масштабируется
целиком относительно ширины контейнера через `cqw`. При ширине до 840 px остаются
надпись и логотипы; потоки, орбита, курсор и вступительные декорации скрыты.
Подписи на мобильном переходят в обычный поток документа.

`audienceDataThreads.js` создаёт 32 основные, 7 крайних, 6 правых крайних,
18 фоновых, 10 правых символьных, 5 центральных символьных и 5 крупных
символьных линий.
Расчёт выполняется при загрузке модуля, не при каждом рендере. Разнообразие задано
фиксированными последовательностями: при перезагрузке композиция сохраняется.

- `getArrivalX` в `audienceDataThreads.js` задаёт положение концов основных потоков
  относительно дуги орбиты. При переносе орбиты нужно согласованно менять её CSS
  и эту геометрию.
- Координаты, длины, яркость и вариация потоков задаются непосредственно в массивах
  `mainThreads`, `ambientThreads`, `edgeThreads` и вспомогательных группах.
  `opacity` — непрозрачность: больше = ярче.
- `duration` и `symbolDuration` задают секунды полного прохода; увеличение замедляет
  движение. Индивидуальные задержки символов задаются через `symbolDelay`.
- `--flow-start-x` — начальная позиция движущегося блика/символов, 70% длины линии,
  а не её ширина. Такое положение сокращает путь при первом появлении.
- `top` в данных — координата самой линии в сцене. JSX учитывает положение слоя
  `--channels-top` и внутренний отступ линии `--thread-line-y` через CSS `calc()`.
- Маска каждой строки смягчает исчезновение по горизонтали; маска общего слоя и
  разная яркость крайних строк отвечают за вертикальное затухание.

Логотипы вырезаются из единой SVG-маски 493×310 px. Координаты в `partners`
одновременно определяют положение логотипа и участок маски/градиента. Внешний
элемент отвечает за рост, внутренний — за покачивание: их `transform` не конфликтуют.

## Курсор и доступность

Положение blur обновляется через ref максимум раз за кадр (`requestAnimationFrame`).
React state содержит только символы: не более 12 групп, не чаще одного добавления
за 85 мс и после перемещения минимум на 14 px. Координаты переводятся из viewport
в систему масштабированной сцены, затем привязываются к сетке 8×12 px.
Группы удаляются после CSS-анимации. Запланированный кадр отменяется при выходе
указателя, pointer cancel и размонтировании.

Blur находится **рядом** с маскированной зоной курсора, а не внутри неё: иначе
маска меняет backdrop root и размытие сцены позади может перестать работать.
Затемнения у эффекта нет. Размер и сила blur задаются в `AudienceCursorTrail.css`.

Декоративные символы и импульсы скрыты от скринридера; у логотипов есть названия.
Touch не создаёт след. При `prefers-reduced-motion: reduce` сцена статична,
декоративное движение отключено, включая псевдоэлементы фоновых линий.

## Результат технического разбора

Разделены стили по ответственности и данные потоков отделены от JSX. Неочевидные
геометрические значения получили имена, устранён скрытый сдвиг `+33` в JSX.
Обработка указателя объединяет события в один кадр; нет постоянного JS-цикла.
Исправлено отключение анимации `::before` в режиме уменьшенного движения.
Новые зависимости не добавлены.

Оставшиеся особенности для production-проверки:

- Орбита подключена как PNG через `audience-data-scene__orbit`; сейчас источник
  берётся из `src/assets/figma/audience-data/planet.png`. Для точной подгонки потоков важны координаты
  и размер этого изображения в `AudienceDataScene.css`.
- `background-position`, маски, drop-shadow и backdrop blur могут требовать
  перерисовки. FPS и стоимость GPU здесь не измерялись; нужен профиль на целевых
  устройствах, особенно Safari и слабых ноутбуках.
- После первого появления циклические CSS-анимации продолжаются вне viewport.
  Если профилирование покажет нагрузку, можно отдельно добавить паузу вне экрана,
  сохраняя прогресс. Сейчас поведение при прокрутке сохранено.
- Переключатель аудитории меняет выбранную кнопку; содержимое этого блока от
  выбранного значения сейчас не зависит. Для разных сценариев потребуется
  передача данных через props.

## Проверка изменений

Обязательные команды из корня: `npm run lint` и `npm run build`.
При рефакторинге дополнительно проверены в Chromium координаты, размеры,
масштаб и тайминги на кадрах 0 / 2,4 / 3,3 / 4,3 / 6,2 / 12 с; конфигурации
всех 83 потоков сравнены с текущей реализацией. Проверены появление и
удаление символов курсора, лимит групп, мобильное скрытие эффектов и отсутствие
анимаций сцены в reduced motion. Для приёмки в браузере откройте `/mads/`,
прокрутите к блоку и проверьте начало анимации после перезагрузки страницы.

## Сохранённое отключённое вступление с плюсиком

Разметка, стили и assets вступления сохранены как обратимый backup. Сейчас
`SHOW_DATA_INTRO = false` в `AudienceDataScene.jsx`, поэтому вступление скрыто,
а основная анимация стартует без дополнительной задержки. Не включать без отдельного
согласования: это изменит текущую последовательность событий.
